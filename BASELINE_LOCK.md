# CCLOS NAND Edition — Baseline Lock

## Canonical user-facing baseline

**CCLOS Public Beta v0.35.2** is the only approved visual/behavior baseline for this project.

Artifact:

`http://consolecrate.xyz/updates/CCLOS_Public_Beta_v0.35.2.zip`

Donor source repository:

`https://github.com/CGameDev/ConsoleCrateLive.git`

Expected source family:

`CCLOS`

## Known provenance gap

At project initialization, `ConsoleCrateNativeStore/ConsoleCrateVersion.h` on the visible `CCLOS` branch reports `0.34.0`, not `0.35.2`.

This is a **hard blocker for implementation, not permission to approximate**.

Codex must locate the source revision that produced the public v0.35.2 package. Once identified, record:

- repository;
- branch/tag if any;
- full commit SHA;
- application version;
- build label;
- public artifact filename;
- SHA-256 of the public artifact if locally available;
- SHA-256 of the imported baseline source manifest.

in `baseline/baseline.lock.json`.

## Required baseline directory model

After provenance is resolved, import the exact public-release source into:

`src/CCLOS/`

Do not rewrite it during import.

NAND-specific code should be introduced around the baseline in clearly named components such as:

- `src/CCLOSNand/`
- `src/XboxSystemBridge/`
- `src/CCLOSRecovery/`
- `tools/CCLOSNandBuilder/`

Where practical, changes to existing CCLOS files should be minimal, reviewable, and tied to a named milestone.

The following are baseline-owned and frozen until the owner explicitly authorizes a UI milestone:

- overall 1280x720 shell;
- top HUD;
- bottom HUD;
- navigation rail;
- page order;
- Home layout;
- Marketplace/Shop layout;
- My Collection layout;
- Queue and Downloads layouts;
- Achievements layout;
- System Health layout;
- Settings layout;
- Network layout;
- Data layout;
- About layout;
- Security layout;
- Watch TV/media layouts;
- Social Hub layout if present in the locked baseline;
- Quick Guide/Control Center appearance if present in the locked baseline;
- focus borders and navigation behavior;
- established colors, translucency and typography;
- icons, artwork treatment and background behavior.

## What NAND work may change without a UI milestone

NAND milestones may change internals needed to make the same CCLOS experience operate from flash, including:

- path/storage abstraction;
- initialization order;
- system-service ownership;
- flash read paths;
- no-storage behavior;
- boot/runtime boundaries;
- resource packing/compression;
- platform bridge interfaces;
- recovery plumbing;
- builder/verifier tooling;
- board/NAND detection;
- console-specific image construction.

Any unavoidable visible status/error text must use the existing CCLOS renderer, typography, geometry and interaction patterns.

## Prohibited substitutions

Do not use screenshots of the public beta as UI backgrounds or fake the interface. Import and build the actual release-equivalent UI/resources.

Do not substitute:

- an autogenerated UI;
- a generic dashboard template;
- an NXE/Metro clone;
- Aurora/FSD layouts;
- Windows-style settings pages;
- a simplified temporary UI that later becomes permanent.

## Baseline acceptance gate

Milestone 0 closes only when all of the following are true:

1. exact v0.35.2 source provenance is known;
2. immutable commit SHA is recorded;
3. baseline source is imported into this repository;
4. baseline builds with the expected Xbox 360 VS2010/XDK toolchain;
5. a source/resource manifest is generated;
6. the public-release navigation/pages can be matched to the imported source/assets;
7. no NAND-specific behavior has yet changed the product;
8. the owner is given a concise baseline report and no ambiguity remains.

Until then, no NAND implementation should proceed.
